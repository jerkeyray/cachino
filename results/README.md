# Released results

Per-request numbers behind the [report](../docs/report.md), as CSV. They hold
token counts, cache hits, predictions, bounds, parity flags and engine timings.
They hold no prompt or reply text, no token IDs and no absolute timestamps; the
raw captures stay private.

```sh
python3 analysis/validate_results.py
```

checks every file against [`SHA256SUMS`](SHA256SUMS), checks each row against
the cache's arithmetic, and recomputes the report's headline numbers from the
rows, using only the standard library. That establishes that the tables are
consistent and support the report's arithmetic; it cannot establish that the
private runs happened as recorded.

The tables are generated by `experiments/release/export_results.py` from the
private run directories, never edited by hand. Each folder's `metadata.json`
gives the run, protocol, engine, model and date.

## Columns

All token counts use the pinned tokenizer and template of the run's model.
Cache hits, predictions and bounds are whole 32-token blocks, never more than
the prompt length minus 1. An **empty cell is an unknown value, never zero**;
only the columns marked *may be empty* can be.

| Column | Meaning |
| --- | --- |
| `run`, `seed`, `sessions`, `limit` | Run directory, engine seed, concurrent sessions, and session limit: `none`, `cap-2` (at most two active sessions), `budget-v1` or `budget-v2` (token budget of 14,016, first and second version; see 3.8) |
| `position` | Order of the request in its run or replay, from 0 |
| `session`, `turn` | Session label within the run, and the turn within that session, from 0 |
| `start_s`, `end_s` | Proxy start and end of the request, in seconds since the run's first request. Proxy time, not engine time |
| `send_s`, `recv_s` | Replay send and receive time, in seconds since the first send |
| `waited_ms` | Time the session limit held the request before forwarding; 0 when it did not wait. *May be empty* in runs recorded before the limit existed |
| `prompt_tokens` | Prompt length from the local render |
| `prompt_tokens_engine` | Prompt length the engine reported; equals `prompt_tokens` wherever the engine reported it |
| `completion_tokens`, `generated_replay` | Tokens the engine generated for the request, live or in the replay |
| `cached_tokens`, `engine` | Prompt tokens vLLM served from its prefix cache (`usage.prompt_tokens_details.cached_tokens`) |
| `predicted`, `predicted_cached`, `predicted_sequential` | The free-queue predictor's hit for the request, replaying requests in sequence |
| `predicted_overlap` | The same predictor holding each request's blocks until it ends. *May be empty* where the predicted cache could not fit the request before its recorded end |
| `predicted_admission`, `predicted_completion`, `predicted_prompt_only` | Overlap predictors that take decode blocks at admission, at completion, or not at all |
| `session_bound` | Longest prefix shared with an earlier prompt of the same session, in whole blocks, capped at prompt length minus 1. Reuse below it was lost to eviction |
| `any_session_bound` | The same over earlier prompts of any session: the naive baseline that assumes matching blocks are still cached |
| `best_lcp`, `adjacent_lcp`, `prompt_bound` | Single sessions: longest shared prefix with any earlier prompt and with the previous prompt, and the first in whole blocks |
| `recomputed`, `new_content`, `previous_reply`, `block_rounding`, `eviction` | Single sessions: recomputed tokens and their split by cause |
| `waited_for_blocks` | 1 if the overlap predictor queued the request because its blocks did not fit |
| `overlapping_requests` | Other requests whose proxy interval overlapped this one |
| `engine_ttft_ms` | vLLM's per-request time to first token, from scheduling. *May be empty* in runs recorded without per-request metrics |
| `delay` | Positions later than recorded that a request ran in a reordered replay |
| `parity` | 1 if the engine's prompt token IDs equalled the local render |
| `num_blocks` | Cache size in 32-token blocks, read back from the engine log |
| `predictor_exact`, `parity_requests` | T4: requests whose prediction, and whose prompt IDs, matched the engine |
| `ttft_round1_s`, `ttft_round2_s` | T4: total time to first token over the 30 requests, per round |
