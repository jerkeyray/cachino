# Naive prefix baseline, 2026-11-08

Question: how much does modeling the cache add over the obvious predictor?

The naive predictor takes, for each request, the longest exact-ID prefix
shared with any earlier prompt, rounds it down to whole blocks, caps it at
prompt length minus 1, and assumes it is still cached. It ignores residency.
Three other predictors are scored the same way against the engine's reported
`cached_tokens`: the same bound within the request's own session, and the
sequential and overlap free-queue predictors.

Inputs are the saved `concurrent-attribution.json` rows; no engine was run.
Scores come from `analysis/matrix_summary.py` (`predictors` field), code after
commit 3941a53. Absolute error is summed over requests each predictor
predicted; no request was left unpredicted.

## Concurrent sessions, 9 seeded runs (concurrency-matrix-20261107)

Qwen3-1.7B, 2 to 4 sessions, 438 blocks, 265 requests.

| Predictor | Exact | Total absolute error (tokens) |
| --- | --- | --- |
| Naive: any earlier prompt, assumed cached | 256 / 265 | 8,320 |
| Own session only, assumed cached | 226 / 265 | 24,064 |
| Free queue, sequential | 259 / 265 | 1,504 |
| Free queue, overlap | 259 / 265 | 352 |

- In the 7 runs without eviction, the naive predictor and the overlap
  predictor were both exact on every request.
- Every miss was in the 2 evicting runs (s1-n3, s2-n4). The naive error there,
  8,320 tokens, equals the reuse those runs lost to eviction (3,680 + 4,640).
- The overlap predictor's remaining error was 224 and 128 tokens in those runs.
- Own-session bounds alone miss cross-session reuse, so they are the worst.

## Session-cap runs, seeds 1 to 5 (limit-matrix-20261108)

Runs `s1-n4` to `s5-n4`, cap off and at 2 (10 runs, 384 requests; three
evicted: s2-n4, s4-n4, s5-n4).

| Predictor | Exact | Total absolute error (tokens) |
| --- | --- | --- |
| Naive | 357 / 384 | 74,752 |
| Own session only | 313 / 384 | 97,088 |
| Free queue, sequential | 367 / 384 | 26,784 |
| Free queue, overlap | 370 / 384 | 5,184 |

## Reading

Without eviction, adjacent-prefix matching already predicts reuse; the cache
model adds nothing there. Its value is on requests where residency matters:
it cut total error by 24x on the 9-run matrix and 14x on the cap runs.
Exact-request counts understate this, because most requests have no eviction.

This scores hit prediction only. A shortfall under overlap can come from
eviction or from blocks not yet ready when the request ran; telling those
apart needs engine-side events.
